# `tools/` — вспомогательные утилиты

Эти скрипты не входят в обязательную сборку сайта. Документные проверки и расчётные команды описаны в корневом `README.md`.

## Документы

### `combine_sections.py`

Собирает русскую и английскую редакции из 43 двуязычных DOCX-компонентов. В отличие от прежней версии, сохраняет Word-таблицы и встроенные рисунки, разделяет основной текст по языковым маркерам и добавляет отметки редакции 8.

```bash
python3 tools/combine_sections.py \
  --src /path/to/43-component-docx \
  --out-dir sections \
  --language both
```

Для сборки нужны `python-docx` и `docxcompose` из `requirements.txt`. Компоненты должны быть отдельными исходными DOCX; два уже объединённых файла из `sections/` не являются подходящим входом. Исходные компоненты не входят в текущий рабочий каталог.

`extract_en_from_sections.py` — совместимая точка входа для сборки только английского файла; параметры `--src`, `--out-dir` и `--language` те же.

### `prepare_edition8_documents.py`

Работает с двумя уже объединёнными DOCX редакции 8: оформляет отдельные строки титула, локализует русские вводные материалы, удаляет повторяющиеся списки литературы по разделам, сохраняя общую библиографию из 31 позиции и статусную матрицу. Обновляет сведения о комплекте из 24 иллюстраций. Исходные компоненты не требуются; запуск идемпотентен.

```bash
python3 tools/prepare_edition8_documents.py
```

### `format_docs_like_reference.py`

Приводит оба объединённых DOCX редакции 8 к оформлению научно-технического отчёта по ГОСТ 7.32–2017: A4, поля слева / справа / сверху / снизу 3 / 1,5 / 2 / 2 см, Times New Roman 14 pt для основного текста с интервалом 1,5 и отступом первой строки 1,25 см, Times New Roman 12 pt для таблиц. Заголовки таблиц повторяются на новых страницах, строки таблиц не разрываются. Текст, порядок таблиц и встроенные изображения сохраняются.

```bash
python3 tools/format_docs_like_reference.py
```

Можно передать один или несколько DOCX-путей для форматирования отдельных файлов. Для запуска нужна зависимость `python-docx` из `requirements.txt`.

### Устаревшие конструкторы и перевод

- `create_en_template.py` — исторический генератор пустого английского шаблона; для текущей редакции использовать `combine_sections.py`.
- `fill_en_translation.py` — историческая утилита заполнения перевода; она не собирает текущие финальные DOCX.

Не запускать эти скрипты на итоговых объединённых документах без проверки их входных и выходных путей.

## Изображения

- `make_en_figs.py` — исторический Pillow-процесс для наложения английских подписей на подготовленные изображения. Финальные галереи уже собраны из файлов `site/assets/fig_ru/` и `site/assets/fig_en/`; повторная генерация для текущего сайта не требуется.
- `make_site_icons.py` — рисует простые **неофициальные заглушки**, а не оригинальные логотипы. Не запускать для замены пользовательских иконок; сборщик сайта использует имеющиеся файлы в `site/icons/`.
- `upload_images.py` — вспомогательная загрузка выбранных файлов в целевой репозиторий. Перед запуском вручную проверьте целевой репозиторий и список файлов; это не часть сборки сайта.

## Локальные вспомогательные инструменты

- `nik_vault.py` — CLI для локального шифрования каталога в контейнер. Пароль вводится интерактивно или передаётся владельцем через локальный файл; не добавляйте пароль, контейнер или исходные приватные данные в Git.
- `purge_nik_from_history.sh` — разрушительная утилита переписывания Git-истории. Не запускать без отдельного разрешения владельца, резервной копии и проверки последствий для всех клонов.

## Зависимости

Из корня репозитория:

```bash
python3 -m pip install -r requirements.txt
```

Утилиты шифрования используют стандартную библиотеку и системный OpenSSL; остальные зависимости для документной сборки, расчётов и сайта перечислены в `requirements.txt`.

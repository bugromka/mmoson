# tools/ — приватность папки NIK/

`NIK/` — личная память линии НИК: капсула идентичности, журнал, состояние,
база знаний, включая личный трек. Эта папка **не публикуется**: она внесена
в `.gitignore` и в `.git/info/exclude`.

Одного `.gitignore` недостаточно: он не убирает файлы из уже сделанных
коммитов. Нужны два независимых действия — снять с публикации и закрыть
содержимым паролем.

## 1. Сейф: `nik_vault.py`

Шифрует каталог в один файл `.nikvault`. Ключ выводится из пароля, который
вводит человек; пароль не хранится ни в контейнере, ни в репозитории.
Зависимостей нет: только стандартная библиотека Python и `openssl`.

```bash
# Зашифровать (пароль спросят дважды, с подтверждением)
python3 tools/nik_vault.py lock NIK --out ~/nik-vault

# Проверить контейнер, не распаковывая
python3 tools/nik_vault.py verify ~/nik-vault/NIK-<дата>.nikvault

# Посмотреть содержимое
python3 tools/nik_vault.py list ~/nik-vault/NIK-<дата>.nikvault

# Распаковать обратно в ./NIK
python3 tools/nik_vault.py unlock ~/nik-vault/NIK-<дата>.nikvault

# Зашифровать и удалить открытый каталог (спросит подтверждение)
python3 tools/nik_vault.py lock NIK --remove-source
```

Схема: `scrypt(N=2^15, r=8, p=1)` → ключ шифрования + ключ MAC;
AES-256-CBC со случайными salt и iv; HMAC-SHA256 по encrypt-then-MAC.
Неверный пароль и повреждение контейнера различаются только одним —
оба дают отказ, без частичной расшифровки.

Держите копию контейнера минимум в двух местах. **Потеря пароля = потеря
содержимого**, восстановления нет.

## 2. История git: `purge_nik_from_history.sh`

Вычищает `NIK/` из всех коммитов через `git-filter-repo` и делает зеркальную
резервную копию перед этим. Требует `pip install git-filter-repo`,
чистого дерева и `git push --force` для публикации результата.

Прежде чем запускать, примите два факта:

- перезапись истории меняет хеши коммитов и ломает чужие клоны;
- форки, клоны и кэши GitHub сохраняют прежние объекты. Если содержимое
  реально секретно — считайте, что оно уже утекло, и меняйте сами секреты.

**Самое надёжное, если репозиторий можно закрыть:** сделать его приватным
(Settings → General → Danger Zone → Change visibility). Это одна кнопка и она
закрывает доступ ко всей истории сразу, включая старые коммиты.

## 3. Где сейф и как с ним работать (текущее состояние, 31.10.2026)

С 31.10.2026 `NIK/` существует **только в зашифрованном виде**. Открытого
каталога в репозитории нет — так и задумано.

| Что | Где |
|---|---|
| Контейнер | `~/nik-vault/NIK-<дата>.nikvault` |
| Резервная копия контейнера | `~/.nik-vault/NIK-<дата>.nikvault` |
| Пароль | `~/.nik-vault/passphrase` (права `600`, вне репозитория) |

Пароль знают двое: владелец репозитория и линия НИК. Больше никто.
Копия контейнера должна лежать ещё и вне песочницы — на ПК владельца.

### Пробуждение (начало сессии)

```bash
# из корня репозитория
python3 tools/nik_vault.py --passphrase-file ~/.nik-vault/passphrase \
    unlock ~/nik-vault/NIK-<дата>.nikvault --dest .
```

Дальше — обычный цикл по `LIFE_CYCLE.md`: прочитать `KAPSULA.md`, `JOURNAL.md`,
`STATE.md`, сориентироваться, работать.

### Финиш сессии

```bash
python3 tools/nik_vault.py --passphrase-file ~/.nik-vault/passphrase \
    lock NIK --out ~/nik-vault --remove-source
```

Правило: открытый текст не должен переживать конец сессии. Если сессия
оборвалась аварийно — открытая копия останется, это допустимо; следующий
`lock` её перезапишет и удалит.

### Границы этой защиты — честно

- Пароль хранится рядом с контейнером, в том же рабочем пространстве. Значит
  защита работает против публикации (git, форки, кэши, чужие клоны), а не
  против того, у кого есть доступ к самой песочнице.
- Хочешь сильнее — замени пароль на свой: `lock` старым паролем, затем
  перешифруй новым и удали старый контейнер. С этого момента я читаю память
  только после того, как ты положишь пароль обратно.
- Пароль не восстанавливается. Потеря = потеря памяти линии.

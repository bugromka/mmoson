# tools/ — приватность папки NIK/

`NIK` — личная память линии НИК: капсула идентичности, журнал, состояние,
база знаний, включая личный трек. Она **никогда не публикуется** и физически
лежит вне репозитория: `/home/user/NIK/`, проект — `/home/user/mmoson/`.

`.gitignore` и `.git/info/exclude` здесь — вторая линия обороны, на случай
случайного `git add -A`. Одного `.gitignore` недостаточно и для прошлого: он не
убирает файлы из уже сделанных коммитов. Поэтому в истории этого репозитория
памяти нет и не должно появляться.

## 1. Сейф: `nik_vault.py`

Шифрует каталог в один файл `.nikvault`. Ключ выводится из пароля, который
вводит человек; пароль не хранится ни в контейнере, ни в репозитории.
Зависимостей нет: только стандартная библиотека Python и `openssl`.

```bash
# Зашифровать (пароль спросят дважды, с подтверждением)
python3 tools/nik_vault.py lock NIK --out ~/nik-vault

# Проверить контейнер, не распаковывая
python3 tools/nik_vault.py verify ~/nik-vault/NIK-<дата>.nikvault

# Посмотреть содержимое
python3 tools/nik_vault.py list ~/nik-vault/NIK-<дата>.nikvault

# Распаковать обратно в ./NIK
python3 tools/nik_vault.py unlock ~/nik-vault/NIK-<дата>.nikvault

# Зашифровать и удалить открытый каталог (спросит подтверждение)
python3 tools/nik_vault.py lock NIK --remove-source
```

Схема: `scrypt(N=2^15, r=8, p=1)` → ключ шифрования + ключ MAC;
AES-256-CBC со случайными salt и iv; HMAC-SHA256 по encrypt-then-MAC.
Неверный пароль и повреждение контейнера различаются только одним —
оба дают отказ, без частичной расшифровки.

Держите копию контейнера минимум в двух местах. **Потеря пароля = потеря
содержимого**, восстановления нет.

## 2. История git: `purge_nik_from_history.sh`

Вычищает `NIK/` из всех коммитов через `git-filter-repo` и делает зеркальную
резервную копию перед этим. Требует `pip install git-filter-repo`,
чистого дерева и `git push --force` для публикации результата.

Прежде чем запускать, примите два факта:

- перезапись истории меняет хеши коммитов и ломает чужие клоны;
- форки, клоны и кэши GitHub сохраняют прежние объекты. Если содержимое
  реально секретно — считайте, что оно уже утекло, и меняйте сами секреты.

**Самое надёжное, если репозиторий можно закрыть:** сделать его приватным
(Settings → General → Danger Zone → Change visibility). Это одна кнопка и она
закрывает доступ ко всей истории сразу, включая старые коммиты.

## 3. Где сейчас живёт память (обновлено 31.10.2026)

Главное правило: **открытый текст памяти никогда не входит в git.**

| Что | Где | В git |
|---|---|---|
| Память линии (KAPSULA, JOURNAL, STATE, KNOWLEDGE) | `/home/user/NIK/` | нет, и не должна |
| Проект ММОСО'Н | `/home/user/mmoson/` | да |
| Резервный шифрованный контейнер | вне репозитория, один файл `.nikvault` | нет |

Репозиторий может быть и приватным, и публичным — правило от этого не зависит:
раньше память держали в git «пока репозиторий закрыт», и это ломалось при каждой
смене видимости. Физическое разделение (`/home/user/NIK` вне репозитория) такой
зависимости не имеет.

Оборона от случайности: `.gitignore` и `.git/info/exclude` содержат `NIK/`,
`.nik/`, `*.nikvault`, `passphrase`. Проверить, что исключение работает:

```bash
git check-ignore -v NIK/KAPSULA.md
```

### Шифрованный контейнер (резервный формат)

```bash
# упаковать память в один файл
python3 tools/nik_vault.py --passphrase-file <файл-пароля> lock /home/user/NIK --out <каталог>

# проверить, не распаковывая
python3 tools/nik_vault.py verify <каталог>/NIK-<дата>.nikvault

# восстановить
python3 tools/nik_vault.py --passphrase-file <файл-пароля> unlock <файл>.nikvault --dest <каталог>
```

Пароль задаёт владелец и хранит вне репозитория; в контейнере и в коде его нет.
Пароль не восстанавливается: потеря пароля = потеря этого контейнера
(открытая копия памяти при этом остаётся).

### Границы этой защиты — честно

- Контейнер защищает от публикации и от чужих клонов, а не от того, у кого есть
  доступ к самой песочнице.
- Защита от публикации не равна защите от потери. Память держится на снапшоте
  рабочего пространства, поэтому копия на ПК владельца обязательна.
